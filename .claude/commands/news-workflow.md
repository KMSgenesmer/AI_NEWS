# 뉴스 수집기 기능 개발 워크플로우

뉴스 수집기 앱에서 새 기능을 개발할 때 브랜치 생성부터 커밋, main 병합, 작업 요약까지 순서대로 진행합니다.
브랜치 이름 : $ARGUMENTS

## 실행 순서

### 1. 현재 상태 확인
- `git status`와 `git branch --show-current`로 현재 상태와 브랜치를 확인해.
- 현재 브랜치가 main이 아니라면 경고를 주고, main으로 이동할지 사용자에게 물어봐. 사용자가 승인하면 이동하고, 거절하면 여기서 멈춰.
- 커밋하지 않은 변경이 있으면 함께 알려주고, 어떻게 할지 물어봐. 사용자의 변경을 임의로 버리거나 덮어쓰지 마.

### 2. 새 브랜치 만들기
- `$ARGUMENTS`가 있으면 그 이름으로 새 브랜치를 만들어줘.
- `$ARGUMENTS`가 비어 있으면 어떤 기능을 개발할 것인지 물어보고, 답변을 바탕으로 영어 소문자-하이픈 형식(예: `add-category-filter`)의 브랜치 이름을 제안해. 사용자가 확인하면 그 이름으로 만들어줘.

### 3. 개발 시작 안내
- 브랜치 생성이 끝나면 "이제 개발을 시작하세요!"라고 안내해.
- `CLAUDE.md`를 다시 읽고 이 프로젝트의 기술 스택과 컨벤션을 요약해서 알려줘. (Next.js 16 App Router, Clerk, Neon + Drizzle, Claude API, 모든 사용자 출력은 한국어, 비밀키는 서버 환경변수로만 관리 등)

### 4. 완료 처리
- 사용자가 '완료' 또는 'done'이라고 입력하면 다음을 진행해.
  1. `git status`로 변경된 파일 목록을 보여줘.
  2. 변경 내용을 바탕으로 커밋 메시지를 자동으로 제안해. 이 저장소의 기존 커밋처럼 한국어로 작성해.
  3. 사용자가 확인하면 변경 파일을 커밋해. `.env.local` 등 비밀키가 든 파일은 절대 포함하지 마.
  4. 커밋 후 main으로 이동해 작업 브랜치를 병합해. 충돌이 나면 임의로 해결하지 말고 사용자에게 알려줘.

### 5. 작업 요약
- 병합이 끝나면 작업 내용을 요약해서 보여줘. (브랜치 이름, 커밋 메시지, 변경된 파일, 주요 변경 내용)
- 푸시는 사용자가 요청할 때만 해.
